# Optimus v8

Release date: 2 November 2026. Git tag: `v8`. Package/API version: `8.0.0`.

## Included

- **myDATA Purchases:** a local monthly and historical review workspace for three represented companies, with accountant participation optional in the application workflow.
- **Read-only AADE intake:** per-company production/sandbox connections; explicit connection tests and month-range sync; durable pagination/cancellation; scoped remote evidence, matching, classification history and cancellations. The reader handles both direct RequestedDoc XML and the Microsoft serialization wrapper observed from production.
- **Document intake:** private encrypted PDF/JPEG/PNG originals, exact-file duplicate detection, manual editing, original previews and optional attachment of a source file to an imported draft. Local PDF layout extraction, Greek/English OCR, embedded-image/rendered QR scanning and optional consented Anthropic text suggestions remain separate from saved facts.
- **QR evidence:** bounded public structured downloads for supported Impact/Entersoftone invoices, plus recognised AADE/receipt/Epsilon Digital verification references. Unsupported links remain inert; provider retrieval is not represented as AADE acceptance.
- **Classification preparation:** official category/E3/VAT dropdowns with Greek labels, explicit workbook pairing filters, server-side checks for new selections and preserved legacy notes. Source URLs/hashes and the original public combinations workbook are pinned locally. Source discrepancies and conditional/historical rules remain visible limitations.
- **Local-upload deletion:** Action-column Delete with purchase/company confirmation, revision checks, extraction cleanup and encrypted-original removal. Linked AADE evidence, audits and existing backups are retained; imported AADE drafts are protected.
- **Recovery and safeguards:** dedicated transactional tables, scoped optimistic revisions, append-only audit events, encrypted module/general backup support, legacy snapshot compatibility and cancellation of pending jobs on restore. Credentials and module keys remain excluded from Git and backups.
- **Startup:** invoice processing does not depend on FFmpeg; Document to Markdown imports its optional conversion implementation only when used.

## Scope

v8 is a read-only intake and editable preparation release. It does not submit invoices or classifications, infer tax eligibility, implement a complete historical tax ruleset, or expose an AADE cancellation method. “Details reviewed” records a check of facts, not accounting/tax approval. Related-document conditions, VAT deduction rights and special/foreign scenarios still require review. There are no unattended production writes.

## Setup and upgrade

Deploy/install the current dependencies and restart Optimus. The idempotent myDATA schema initializes during normal startup and starts its durable workers. Configure [private connection slots](../configuration.md#read-only-aade-connections), save each company profile, test its selected environment, then explicitly sync a month. Test connection is a read check; it does not select the sandbox. Sandbox requires separate test registration/credentials.

Preserve `data/.mydata.key` separately from encrypted backups and from `.env`. Original files and credentials are local installation state, not release assets. Existing draft/extraction backups remain supported. Restore invalidates review/revisions and cancels pending reads/extractions; no production queue is resumed.

See [workflow and limits](../tools/mydata-invoices.md), [API](../api.md), [database](../database.md), [backup/restore](../operations/backup-restore.md) and [deployment](../operations/deployment.md).

## Verification

The release is checked with the complete backend suite against isolated PostgreSQL schemas and synthetic fixtures, plus the React production build. Automated tests mock upstream calls. UI checks exercise intake, editable drafts, classification selections and the delete confirmation using a synthetic preview. A production RequestDocs response was separately checked during troubleshooting without adding private invoice data or credentials to source fixtures.
